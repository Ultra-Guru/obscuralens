# ObscuraLens v5.0 — what's new

v5.0 is the largest release since v2.0: the platform grows from 10 to **14
target kinds**, gains a **local-first analyst toolbox**, an **advanced
analysis package** (batch fan-out, webhook alerts, pattern-of-life,
geospatial profiling, self-contained HTML reports), a **complete web
application rewrite** and a **one-command launcher**. Nothing you know from
v4.0 moved: every v4 command, endpoint, MCP tool and config key keeps
working exactly as before; v5.0 only adds.

The one-page summary:

| Area | v4.0 | v5.0 |
|---|---|---|
| Target kinds | 10 | **14** (+ MAC, IBAN, IMEI, coords) |
| CLI commands | 40+ | 40+ **+ 16 new** (`mac`, `iban`, `imei`, `coords`, `tools …`, `report`, `patterns`, `geo …`, `alerts …`) |
| MCP tools | 18 | **34** |
| REST endpoints | 25 | **40+** |
| Offline data packs | 3 | **7** (+ OUI, TAC, IBAN structures, country centroids) |
| Web UI | server-rendered dashboard | **single-page application**, 10 views, ⌘K palette, themes |
| Launch | `run.sh` / manual install | **`./start.sh`** — venv + deps + serve + open browser |

## The four new trackers

Each new kind follows the tracker contract you already know: parallel fan-out
to every enabled source, field-level provenance, source-health recording,
history storage, `--risk` support, batch support and MCP/API surfaces.

| Kind | Command | Example input | What it answers |
|---|---|---|---|
| `mac` | `obscuralens mac` | `B8:27:EB:AA:BB:CC` | which organisation made this NIC — vendor, assignment type, locally-administered / privacy-MAC hints, Docker vNIC decode, EUI-64 / IPv6 interface-id derivation |
| `iban` | `obscuralens iban` | `DE89 3704 0044 0532 0130 00` | is this IBAN structurally valid, which country and bank does it belong to (checksum verdict, bank code, account slice, BIC + bank name when openiban answers) |
| `imei` | `obscuralens imei` | `356938035643809` | which device is this — TAC, reporting body (PTCRB/BABT/TAF…), manufacturer + model from the offline TAC pack, Luhn verdict, IMEISV software version |
| `coords` | `obscuralens coords` | `48.8584, 2.2945` · `31U DQ 48288 11087` | what is at this point on Earth — address, city/region/country, elevation, geohash, Maidenhead, DMS/DDM/UTM/MGRS re-encodings, solar position |

Two design notes worth knowing:

- **Offline-first.** MAC, IBAN and IMEI intelligence is primarily offline
  (curated IEEE OUI pack, TAC pack, per-country IBAN structure pack); the
  online sources (macvendors, maclookup, openiban, Nominatim,
  BigDataCloud, Open-Elevation) *enrich* the answer rather than gate it.
  A `coords` lookup still returns geohash, Maidenhead, UTM, MGRS, timezone
  and solar fields with the network down.
- **Validate before you transmit.** IBAN mod-97 and IMEI Luhn checks run
  *before* any source is contacted — a typo'd identifier never leaves your
  machine. A pack miss (an OUI or TAC outside the curated subset) is an
  expected answer, never a source failure, so the circuit breaker never
  trips on ordinary misses.

Full source catalogs: [docs/sources.md](sources.md).

## New sources on the existing trackers

- **Username** +4 HTML platforms: **Patreon, Etsy, Substack, Replit** (45
  platforms total: 38 HTML + 7 JSON API). Patreon and Etsy sit behind
  aggressive bot walls — the verdict rules report `unknown` honestly instead
  of a false hit; Substack and Replit produce real found / not-found splits.
- **IP** +`ipapi.is` (geo, ASN, company, datacenter/VPN/proxy/tor flags,
  risk score) and +`ipinfo.io` (country, org, hostname, coordinates), both
  keyless; the `threat_feeds` source now also answers `urlhaus_listed` /
  `threatfox_listed`.
- **Domain** +`doh.google`: DNS-over-HTTPS resolution of A/AAAA/MX/NS via
  dns.google, cross-checking the classic DoH source field-for-field.
- **CVE** +`circl`: CIRCL cveproxy records (current CVE-5.1 schema and the
  legacy flat schema), merged onto the NVD field names so provenance stacks.
- **Crypto** +`mempool.space`: keyless BTC explorer reusing
  blockchain.info's field names (balance, received/sent, tx count) plus a
  pending-tx counter.
- **Intel feeds** +**URLhaus** (abuse.ch malicious-URL host network list)
  and +**ThreatFox** (recent IOC export; the keyed JSON API now needs an
  Auth-Key, so ObscuraLens consumes the keyless CSV export).

## The analyst toolbox (`obscuralens tools …`)

Seven experimental modules, wired to the CLI, the web UI's Tools view, the
REST API and MCP:

| Tool | Command | One-liner |
|---|---|---|
| Encoders | `tools encode` / `tools decode` | encode one input through every scheme at once; auto-decode ranks schemes by readability |
| JWT | `tools jwt` | decode + inspect a compact JWS token (claims timeline, alg risk, key hints) — never verifies signatures, by design |
| Hash ID | `tools hash-id` | structural digest identification with ranked candidates and honest same-length ambiguity |
| Entity extract | `tools extract` | pull every OSINT pivot target out of free text, validator-confirmed; reversible redaction |
| Typosquats | `tools squat` | 15 lookalike families with a 0–100 deception-risk score |
| EXIF | `tools exif` | zero-dependency JPEG/PNG/GIF/BMP/WebP metadata triage — **fully local** |
| Stego | `tools stego` | PNG/BMP/GIF LSB plane statistics, entropy profile, embedded-file carving — **fully local** |

The privacy posture is deliberate: EXIF and steganography analysis are
exactly the tasks people otherwise paste into random online "metadata
viewers" — leaking the very evidence they are investigating. Both modules
run entirely in-process and never touch the network. The one toolbox caveat
is the reverse: JWT inspection treats decoded payload claims as
attacker-controlled data until a signature is verified with real key
material, which this module deliberately does not attempt.

Full details, output shapes and honest limitations:
[docs/experimental.md](experimental.md#toolbox-v50).

## The advanced package (`obscuralens/advanced/`)

Five analysis engines over your stored history and live lookups:

| Module | Entry point | What it does |
|---|---|---|
| `batch` | `run_batch(kind, targets, risk, max_workers, …)` | fan one kind out over many targets, thread pool, per-target envelopes |
| `alerts` | `alerts configure/notify/recent/test` | webhook notifications on `lookup_failed`, `watch_diff`, `risk_high`, `source_tripped` |
| `patterns` | `pattern_report(kind, value)` | pattern-of-life report for one target from its stored history (frequency, gaps, burstiness) |
| `geospatial` | `country_breakdown`, `targets_by_country`, `geohash_clusters`, `most_looked_up_regions`, `to_geojson`, `geo_profile_summary` | geographic footprint of everything you have looked up, with GeoJSON export |
| `report_builder` | `build_report(kind, target)` | one self-contained HTML investigation report (embedded CSS, no external assets) |

CLI surface: `obscuralens report`, `patterns`, `geo profile|clusters|regions`,
`alerts show|set|test`, and the existing `batch` command. REST surface:
`/api/tools/batch`, `/api/report/{kind}/{target}`, `/api/patterns`,
`/api/alerts`. One privacy note: alerts deliver a webhook POST to a URL you
configure — that is data leaving your machine, so point it at an endpoint
you control. Full guide: [docs/advanced.md](advanced.md#advanced-analysis-v50).

## The new web UI

`obscuralens serve` now ships a single-page application from
`obscuralens/web/static/` — no build step, no CDN, no external assets; it
works fully offline once installed. Ten views in three sidebar sections:

- **Workspace**: Dashboard (stat cards, lookups-over-time chart, kind
  donut, source-health bars, recent activity), Lookup workbench (15 kind
  pills, provenance-tracked fields table, risk panel, threat-intel panel,
  recent strip), History (filters, search, CSV export).
- **Investigation**: Investigate (force-directed entity graph, expandable
  nodes, side-panel actions), Timeline (day-grouped event rail), Cases,
  Watchlist.
- **Platform**: Sources (catalog + health), Tools (eight tabs: encode/decode,
  JWT, hash ID, coordinates, extract, typosquats, drag & drop file analysis,
  batch), Settings (API keys, runtime config, webhook alerts).

Global conveniences: **⌘K / Ctrl-K command palette** with fuzzy matching and
`kind:` autocomplete, `/` quick search, `T` theme toggle, `g`+key
navigation, dark theme by default with a persisted light theme, backend
status polling in the sidebar footer, and deep-linkable URLs
(`#/lookup?kind=ip&target=8.8.8.8`).

Full tour with screenshots-level detail: [docs/web-ui.md](web-ui.md).

## One-command start

```bash
git clone https://github.com/Ultra-Guru/obscuralens.git
cd obscuralens
./start.sh            # Linux/macOS
# start.ps1           # Windows
```

The launcher creates `.venv` (reusing it when present), installs the package
with the `[web]` extra, starts `obscuralens serve --open` on
http://127.0.0.1:8000 and opens the browser. Flags: `--no-open` (headless),
`--port N`. `make start` / `just start` do the same. The older `run.sh` /
`run.ps1` (CLI-oriented, per-command) are unchanged.

## New offline data packs

| Pack | Entries | Format |
|---|---|---|
| `oui.txt` | 766 curated IEEE OUI assignments | `AABBCC\|Vendor Name` |
| `tac.txt` | 139 TAC entries | `TAC8\|Manufacturer\|Model-hint` |
| `iban_structures.txt` | 124 country structures | `CC\|length\|bank_code_len\|account_len\|Country name` |
| `country_centroids.txt` | 115 country centroids | `CC\|lat\|lon\|name` |

They ship as package data (works from wheels and the standalone exe) and
are parsed with case-sensitive registry casing preserved — "Cisco Systems,
Inc" never lowercases into mush.

## Upgrading from v4.0

- Nothing breaks: all v4 commands, endpoints, tools, config keys and the
  SQLite schema carry over. The history database, watchlist, cases, source
  health and cache are untouched.
- The web dashboard at `/` is the new SPA; `/docs` (OpenAPI) stays exactly
  where it was.
- The username tracker now sweeps 45 platforms (was 41) — the four new
  platforms were chosen with honest verdict rules, so expect `unknown`
  (not hits) from bot-walled Patreon/Etsy.
- The `experimental_features` master switch covers the toolbox CLI as well;
  set it to `false` to hide the whole surface in one place.
